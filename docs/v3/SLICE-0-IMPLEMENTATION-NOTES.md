## C. Security evidence and limits

**Verified deterministically:** missing/remote/V2 URL configurations and URL tricks are refused; only the exact local profile is accepted. A different workdir is refused. Config/migration discovery is pinned and remote-link files are rejected by the guard. Wrong database markers and database unavailability fail closed before authentication. Proxy returns a sanitized no-store failure. Child processes do not inherit V2 dotenv values or paid-provider keys; original dotenv fixture bytes stay unchanged. Application content uses a request-scoped publishable-key/user-session client, not the service capability. Each foundation operation verifies identity, scopes reads and writes by that identity, ignores forged ownership, rejects malformed IDs without a database write, rejects poisoned foreign receipts, and hides private insert/update errors. Real AI adapter construction is disabled.

**Prepared, not yet verified live:** anonymous denial, fresh password authentication, two-account read/write isolation, direct RLS enforcement, owner-column mutation denial, settings ownership, invalid session/logout/reauthentication, no-store HTTP responses, account switching and private rendered-data isolation. The HTTP suite submits the foundation action to a public route without a session to check its independent authorization. It also attempts forged owner creation and foreign-ID renaming. No two-account result is claimed from deterministic fixtures.

**Company C1:** the migration grants no authenticated Company DELETE and defines no delete/archive RPC, archive column or research-data cascade. The app has no delete/archive action. Future migrations must add indexed composite owner/Company foreign keys with `ON DELETE RESTRICT`. The integration suite includes a transient rollback-only child-FK probe and catalog checks, but those have **not run**. Full populated-child-category, transactional empty-delete and concurrent create/delete tests remain deferred until those separately authorized child migrations/actions exist. C1 is protected by keeping deletion unavailable; it is not comprehensively validated for future content.

No credential values were written to source, reports or command output. CLI credential-bearing output is captured and suppressed; the privileged local key would enter only the integration-test child, never the application. No synthetic accounts were actually created because runtime preflight never reached fixture setup. The early broad port bindings are a real discovered setup issue; they were stopped before test users/content and must not be waived on the next attempt.
