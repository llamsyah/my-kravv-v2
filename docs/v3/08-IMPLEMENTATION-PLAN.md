Status: **Draft — awaiting owner review**

Authority: [V3 index](00-V3-INDEX.md). **Planning only.** This sequence is derived from the new drafts; it accepts none of them and authorizes no application, database, authentication or provider work. It replaces no historical V2 plan in the archive. There are no delivery dates, tickets or selected migration strategy here.

## Dependency and review rules

Review the [foundation](01-PRODUCT-FOUNDATION.md) and [workflow/domain distinctions](02-WORKFLOWS-AND-INFORMATION-ARCHITECTURE.md) before implementation planning is accepted. Resolve owner choices P1–P8 and technical questions T1–T7 only as they become dependencies for the next bounded slice; do not silently choose the defaults illustrated by a PNG.

Formal recording depends on recoverable authoring and unambiguous Thought/candidate identity. AI Review depends on stable snapshot identity, context selection and accounting, but manual authoring/recording does not depend on AI availability or approval. Reference reuse requires ownership/provenance, not PDF hosting. Account recovery requires designed callback/session handling, not merely a settings screen.

Minimal usage/budget visibility should accompany the AI-review slice rather than display fabricated data in advance. Stage 1 account settings can establish identity/appearance and mark unavailable usage honestly. It need not invent a dashboard to fill the screenshot layout.

This order is a recommendation, not a rigid user workflow or mandatory six-release schedule. Small read/write slices can be reviewed independently; useful manual authoring and recording should not be held behind an unfinished AI feature. If a dependency remains unresolved, continue only work independent of that question and return the blocking choice for review.

## Scope and regression discipline

Each later approved slice should state the accepted contracts it implements, the existing V2 behaviors it preserves or deliberately changes, the evidence required, and any separate environment/provider authorization. Reuse owner/session boundaries, RLS checks, operation identities, draft-receipt logic and conservative accounting where they fit; redesign the V3 authoring/domain/navigation contracts described in [architecture](06-TECHNICAL-ARCHITECTURE.md).

Do not insert a custom template manager, hosted source documents, collaboration, notification system, general chatbot, market terminal, automatic trading or unrelated preferences into these stages. A source icon, inactive template control, sample status, review chat box or settings subsection is not scope approval. Basic usability does not require implementing every mockup asterisk/tab/action.

Use the [validation matrix](07-VALIDATION-AND-RECOVERY.md) to define meaningful checks rather than copying layout snapshots as tests. Database and provider work need their own reviewed operations and evidence. Rollback/data continuity decisions must be settled before persistence changes; this document does not supply or execute migrations.

The 14 reference PNGs remain canonical and untouched. Image compression/conversion, if desired, is a separate explicitly reviewed operation after documentation consolidation. This task ends with locally reviewable documentation, not a commit, push, release or implementation start.
