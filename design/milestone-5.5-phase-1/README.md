# Phase 1 — actual application visual QA

These are unretouched captures of the running MY KRAVV Next.js app, not new static
prototypes. All account/Company/Thought/proposal content is disposable and fictional.
The proposal was generated by an injected local mock; no real AI provider was called.
Fixture account/records were removed and cleanup verified after inspection.

Six existing screens were checked at 1440×1000, 768×1000, 390×844 and 320×844 CSS
viewports; two extra cases cover archive and source-limit generation. Final 26
cases show no document overflow, no measured input text below 16px, no measured
visible native button/navigation/disclosure below 44px high, and both local font
families available with loaded font status. Keyboard focus/disclosure, field errors,
disabled generation, long identity and multilingual text were inspected. This is
not an exhaustive accessibility or interaction-state audit.

The in-app browser's viewport/capture surfaces apply scaling and sometimes trim
pixels. Overrides were compensated to match DOM-reported CSS widths; this is not
proof of native zoom or DPR. Some full-page captures place fixed navigation within
the exported sheet. Exact files may be larger than their CSS viewports; consult the
manifest. Native 100% zoom, actual phone keyboard, screen-reader interaction,
forced font failure and text-zoom reflow remain manual implementation QA items.
No application code was modified for image export, and no screenshots were edited.

Repeatable development fixtures use `scripts/phase-1-visual-fixture.ts` with the
explicit `MY_KRAVV_LIVE_TESTS=development` guard and server-only development env.
Its `setup`, `populate`, and `cleanup` modes manage only its identified disposable
account; credentials remain in an ignored local file and are never printed.
Populate is deliberately single-use and injects mock AI responses, not the configured
provider. Do not reuse this helper on production or actual user records.

preserved behavior, full test results and later-phase boundaries.
